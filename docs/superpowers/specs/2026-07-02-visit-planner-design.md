# 訪問調整アプリ（visit-planner.html）設計書 v3

作成日：2026-07-02
状態：v3 — UI/UXデザイナー＋シニアエンジニアの2体レビュー（計24件）＋Codexレビュー（7件）を反映

## 1. 目的

ケアマネジャーの月間訪問調整を「見える化」する。
**「月間カレンダーに、利用者の名前ピースをはめ込んでいく」**メタファーで、
抜け漏れ・偏り・空き枠・利用者都合との調整をひと目で把握できるようにする。

- 未配置プールが空になったら今月の調整完了
- プールに残っているピース＝未調整の人

## 2. 前提・確定要件

| 項目 | 決定 |
|------|------|
| 方式 | **案A：単一HTML + localStorage**（schedule_v4・お客様ノートと同方式） |
| ファイル | `visit-planner.html` |
| 利用者数 | 20〜40名程度 |
| 訪問頻度 | **全員が月1回**（1人＝1ピース。プールが空＝全員調整済み） |
| 1日の枠 | 訪問①②③の3枠制。既定時刻 ①13:00 ②14:30 ③16:00、枠内で時刻微調整可 |
| カレンダー | **土日も配置可**の7列（日〜土）表示 |
| 都合メモ | NG曜日（チェック式・複数可）＋自由メモ。**NG曜日へのドロップは警告付き確認** |
| 端末 | 主にPC。**D&DのみPC専用**。スマホは閲覧＋✓チェック＋クリック配置（来月予約含む）可 |
| 月替わり | 「前月コピー」「まっさら」を選択 |
| 重要フロー | 訪問済みチェック→その場で来月の予約を入れる |
| 将来 | Googleカレンダー連携（2段構え。本スペックのスコープ外） |

## 3. 画面構成

1画面構成。左に未配置プール、右に月間カレンダー。

```
┌────────────────────────────────────────────────┐
│  ◀ 2026年7月 ▶   未配置: 8名 / 全体 32名   [👥利用者管理]│
├──────────────┬─────────────────────────────────┤
│ 未配置プール      │  月間カレンダー（日〜土の7列）             │
│ [🔍検索____]     │ │ 1(水) 2/3│ 2(木) 1/3│ 3(金) 2/3│…    │
│ [佐藤さん]       │ │①田中✓   │①        │①山本    │      │
│ [鈴木さん ⚠午前NG]│ │②高橋    │②佐野✓   │②        │      │
│ [山田さん ⚠火NG] │ │③        │③        │③川口    │      │
│  …（独立スクロール）│ └──────┴──────┴──────      │
└──────────────┴─────────────────────────────────┘
```

### レイアウト方針（想定解像度：1366×768で成立させる）

- カレンダーは**1枠＝1行の圧縮表示**（名前のみ。時刻・メモはピースの詳細ポップオーバーで表示/編集）
- プールは独立スクロール。カレンダーは全体を優先表示し、収まらない高さのときのみ縦スクロール
- 各日セルのヘッダーに**埋まり数「2/3」**を表示（偏り・空き枠の把握用）

### 構成要素

- **ヘッダー**：月ナビ（◀ ▶）／「未配置: N名 / 全体 M名」カウンター／「👥利用者管理」ボタン
- **未配置プール（左）**：当月未配置のピース一覧。**五十音順**、検索ボックス付き。ピースには名前＋NG曜日バッジ（⚠火NG）
- **月間カレンダー（右）**：各日に①②③の3枠
- **利用者管理（モーダル）**：名前・NG曜日チェック（日〜土）・自由メモの登録／編集／削除。「今月をリセット」（当月配置を全消しして月替わりダイアログを再表示）と「**JSONエクスポート／インポート**」（データのバックアップ・復元）もここに置く

### 配置済みピースの操作面の分離（クリック競合の防止）

配置済みピースには3つの操作があるため、当たり判定を明確に分ける：

| 操作面 | 動作 |
|--------|------|
| ピース本文クリック | **詳細ポップオーバー**を開く（時刻編集・メモ表示・［移動］［プールに戻す］ボタン） |
| ✓エリア（右端24px以上・分離） | 訪問済みトグル（4.3のフロー） |
| ドラッグ（PC） | 移動（4.2） |

クリックでの移動は、詳細ポップオーバーの［移動］ボタンから**移動モード**に入る（プールのピースのクリック選択と同じバナー表示）。

### ピースの4状態スタイル（色だけに頼らず形状差を併用・WCAG AAコントラスト）

| 状態 | スタイル |
|------|---------|
| 空き枠 | 破線枠＋薄い「①」ラベル |
| 配置済み（未訪問） | 実線カード・通常色 |
| 訪問済み | グレーアウト＋✓アイコン。来月予約済みなら**「📅8/5」バッジ**を併記 |
| NG曜日に配置済み | ⚠バッジを常時表示 |

## 4. 操作フロー

### 4.1 配置

**方法A：ドラッグ＆ドロップ（PC専用）**

1. プールのピースを日付枠①②③へドラッグ
2. **ドラッグ開始時、その利用者のNG曜日の列を赤系背景で薄く塗る**（事前可視化）
3. ドロップ先枠は強調ハイライト（schedule_v4の挿入インジケーター相当）
4. NG曜日へのドロップは確認ダイアログ「⚠火曜NGの方ですが配置しますか？」（OK→配置／キャンセル→戻る）
5. 配置時、枠の既定時刻（①13:00 ②14:30 ③16:00）が入る。時刻は詳細ポップオーバーで編集
6. 埋まっている枠へはドロップ不可（枠は1人まで）

**方法B：クリック配置（PC・スマホ共通）**

1. プールのピースをクリック→選択状態（ハイライト＋「配置する枠をクリックしてください［キャンセル］」バナー）
2. カレンダーの空き枠をクリック→配置（NG曜日なら同じ確認ダイアログ）

### 4.2 移動・戻し

- 配置済みピースは別の日・枠へドラッグ移動（NG警告は移動時も適用）。クリックの場合は詳細ポップオーバーの［移動］→空き枠クリック
- プール領域へドラッグ（または詳細ポップオーバーの［プールに戻す］）で未配置に戻す（時刻・✓はリセット）
- 移動は `movePlacement(source, target)` で行い、**重複判定は移動元を除外して**行う（addPlacement＋isPlacedInMonth を素通しすると自分自身に引っかかるため）
- **アンドゥ**：配置・移動・プール戻しの直後にトースト「山田さんをプールに戻しました［元に戻す］」を5秒表示（直前1操作のみ）

### 4.3 訪問済み→来月予約（重要フロー）

1. 配置済みピースの**✓（右端に分離した24px以上のヒットエリア）**をタップ→訪問済み
2. 「来月の予約を入れますか？」確認——**カスタムモーダル必須**（「はい／いいえ／キャンセル」の3択。ブラウザ標準の confirm は2択のため使えない）
   - **来月にすでに配置済みの人にはこのダイアログを出さない**（重複予約防止）
   - キャンセル→**✓も取り消す**（誤タップ対策）
   - いいえ→✓のみ確定
   - はい→**予約モード**へ
3. 予約モード：来月カレンダーに切り替わり、上部に固定バナー「予約モード：山田さんの来月の枠を選んでください［当月に戻る］」。空き枠をクリック（またはD&D）で配置→**自動で当月表示に戻る**
   - **予約モード中は月替わりダイアログを出さない**。来月が未初期化でも `initializedMonths` には**入れない**（あとで通常表示したとき、既存予約を保持したまま通常どおり初期化ダイアログを出す）
4. ✓の再クリックで解除可。解除しても来月予約は残す（削除は来月側で）。**再✓時、来月に配置済みならダイアログは出さない**

### 4.4 月替わり

**トリガー**：`initializedMonths` に含まれない月を開いたときダイアログ表示（配置データの有無では判定しない——来月予約があると配置が先に存在するため）。選択後にその月を初期化済みとして記録する。

```
8月の配置をどうしますか？
┌────────────────────────────────────────┐
│ [前月コピー]  28名を7月と同じ日・枠で配置します       │
│              （3名はプールへ・2名は予約済み）        │
│ [まっさら]    予約済み2名以外をプールから手で配置      │
└────────────────────────────────────────┘
```

- ダイアログに**プレビュー件数**（配置される人数・プール行き人数・予約済み人数）を表示
- 前月にデータがなければ「前月コピー」は無効化
- **「まっさら」でも既存の予約（4.3で入れたもの）は保持**し、それ以外の全員をプールに置く（予約まで消すのは「今月をリセット」のみ）

**前月コピーの処理順（衝突解決）：**

1. 既存の予約（4.3で入れたもの）を先に確定
2. コピーは**空き枠のみ**に行う。予約と同日同枠で衝突した人はプール行き
3. すでに当月に配置済み（予約済み）の利用者はコピー対象外
4. 当月に存在しない日（例：1/31→2月）の配置はプール行き
5. 訪問済み✓はコピーしない（全員 done: false）
6. 結果を「28名配置・3名はプールへ」の形で報告

**やり直し**：利用者管理の「今月をリセット」で当月配置を全消し（予約由来の配置も含む・確認あり）→ダイアログを再表示。

## 5. データ構造（localStorage）

ストレージキー：`visit-planner-v1`

```json
{
  "version": 1,
  "users": [
    { "id": 1, "name": "山田", "ngDays": [2], "memo": "午前は通所" }
  ],
  "placements": {
    "2026-07": [
      { "userId": 1, "date": "2026-07-08", "slot": 1, "time": "13:00",
        "done": false, "gcalEventId": null }
    ]
  },
  "initializedMonths": ["2026-07"],
  "nextId": 2
}
```

- `ngDays`：NG曜日の配列（0=日〜6=土）
- `slot`：1〜3（訪問①②③）
- `gcalEventId`：将来のGoogleカレンダー連携用に最初から予約（常に null で開始）
- **不変条件**：placement は必ず `date.slice(0, 7)` と一致する月キーに格納する
- **書き込みの一元化**：配置の**追加**は全経路（D&D・クリック配置・来月予約・前月コピー）で `addPlacement(userId, date, slot, time)` を通す。**移動**は `movePlacement(source, target)`（移動元を除外して重複判定）
- **重複ガードの一元化**：`isPlacedInMonth(list, userId)` を全配置経路で通し、同一利用者の同月2回配置を防ぐ（list＝対象月の placements 配列）
- 保存は変更のたびに即時。localStorage は try/catch ラッパー経由
- **バックアップ**：利用者管理から JSON ファイルのエクスポート／インポートが可能（localStorage消失時の逃げ道）

## 6. エッジケース・エラー処理

| ケース | 挙動 |
|--------|------|
| 利用者を削除 | 全月の配置済みピースも削除（確認ダイアログあり） |
| 埋まった枠への配置 | 受け付けない（視覚的に不可を示す） |
| localStorage保存失敗（容量超過等） | 画面上部に警告バナー表示 |
| JSON.parse失敗・型不正 | 初期データで起動＋警告バナー。各フィールドは型検証しデフォルト補完 |
| users に存在しない userId の placement（孤児） | ロード時に除去（カウンターを狂わせない） |
| 月キーと date の不整合 | ロード時に date 側を正として正しい月キーへ移送 |
| 月替わりダイアログで前月にデータなし | 「前月コピー」を無効化 |
| 利用者0名 | プールに「👥利用者管理から登録してください」の案内表示 |
| スマホで開いた場合 | D&Dのみ無効（✓・クリック配置・予約は可）。レイアウトは縦積み |

## 7. 技術方針

- 単一HTMLファイル・外部依存なし（オフライン動作）
- **日付処理はローカルタイム固定**：日付文字列は `getFullYear/getMonth/getDate` から組み立てる。`toISOString()`・`new Date("YYYY-MM-DD")`（UTC解釈）は使わない。曜日判定は `new Date(y, m-1, d).getDay()`
- **スマホ判定**：`matchMedia('(pointer: coarse)')` を基本に画面幅を併用。D&Dリスナーのみ無効化
- D&D実装（schedule_v4 の実績パターンを拡張）：
  - `dndState = { userId, source: 'pool' | { date, slot } }` の判別共用体。ドロップ先も pool／枠の2種で分岐
  - drop ハンドラでは操作内容（移動元・移動先・元データ）を **`pendingDrop` に退避**してから「dndState リセット→ハイライト全消去」を同期で完了。NG確認ダイアログは `setTimeout(0)` に逃し、OKなら pendingDrop を適用・キャンセルなら破棄（何も変更しない）→再描画
  - `renderAll()` 先頭で D&D 中の再描画ガード
  - ✓クリックとドラッグの誤発火防止に `calChipDragging` 方式のフラグを流用
  - リスナー多重登録防止（コンテナ再生成 or removeEventListener）
- **ロジックの純関数分離**：`/* CORE:START */…/* CORE:END */`＋`module.exports` ガード（お客様ノート parseCard 方式）。引数はすべてプレーンデータ（Dateオブジェクト不使用・日付は文字列）：
  - `copyFromPrevMonth(prevList, existingList, users, targetMonth)` → `{ placements, pooled, skipped }`
  - `movePlacement(list, source, target)` → 新しい list（移動元を除外して重複・空き判定）
  - `isNgDay(user, dateStr)`
  - `isSlotFree(list, dateStr, slot)`
  - `isPlacedInMonth(list, userId)`
  - `countUnplaced(users, list)`
- 文字コード：UTF-8。Write/Editツールで編集（PowerShell経由で書かない）

## 8. スコープ外（YAGNI）

- Googleカレンダー連携（フェーズ2で別途設計。`gcalEventId` フィールドのみ先行予約）
- 複数ケアマネ対応・共有機能
- 地区情報・移動時間の最適化
- 印刷対応（要望が出たら追加）
- スマホでのD&D操作
- 複数段階のアンドゥ（直前1操作のみ）

## 9. テスト計画

- **純関数の単体テスト（node --test）**：
  - `copyFromPrevMonth`：存在しない日→プール行き／予約済み利用者の除外／予約枠との衝突→プール行き／done リセット／件数報告
  - `movePlacement`：同月内移動が自分自身の重複判定に引っかからないこと／埋まった枠への移動拒否
  - `isNgDay`・`isSlotFree`・`isPlacedInMonth`・`countUnplaced` の境界値
  - ロード時サニタイズ（parse失敗・孤児 placement・月キー不整合の移送）
- **ブラウザ動作確認**：D&D配置／クリック配置／NG事前ハイライト＋警告（キャンセルで変更なし）／詳細ポップオーバー（時刻編集・移動・プール戻し）／アンドゥトースト／✓→予約モード→自動復帰（未初期化の来月でダイアログが出ないこと）／✓キャンセル時の取り消し／月替わりダイアログ（プレビュー件数・まっさら時の予約保持・リセット）／利用者管理CRUD／JSONエクスポート・インポート／リロード後のデータ保持
- **レイアウト確認**：1366×768 で1画面に成立すること
- **スマホ確認**：縦積み表示・D&D無効・✓とクリック配置が動くこと
