# 訪問調整アプリ（visit-planner.html）設計書

作成日：2026-07-02
状態：ユーザー承認済み設計（セクション①②を対話で承認）

## 1. 目的

ケアマネジャーの月間訪問調整を「見える化」する。
**「月間カレンダーに、利用者の名前ピースをはめ込んでいく」**メタファーで、
抜け漏れ・偏り・空き枠・利用者都合との調整をひと目で把握できるようにする。

- 未配置プールが空になったら今月の調整完了
- プールに残っているピース＝未調整の人

## 2. 前提・確定要件

| 項目 | 決定 |
|------|------|
| 方式 | **案A：単一HTML + localStorage**（schedule_v4・お客様ノートと同方式） |
| ファイル | `visit-planner.html` |
| 利用者数 | 20〜40名程度 |
| 訪問頻度 | **全員が月1回**（1人＝1ピース。プールが空＝全員調整済み） |
| 1日の枠 | 訪問①②③の3枠制。既定時刻 ①13:00 ②14:30 ③16:00、枠内で時刻微調整可 |
| カレンダー | **土日も配置可**の7列（日〜土）表示 |
| 都合メモ | NG曜日（チェック式・複数可）＋自由メモ。**NG曜日へのドロップは警告付き確認** |
| 端末 | 主にPC。D&DはPC専用、スマホは閲覧のみ |
| 月替わり | 「前月コピー」「まっさら」を選択 |
| 重要フロー | 訪問済みチェック→その場で来月の予約を入れる |
| 将来 | Googleカレンダー連携（2段構え。本スペックのスコープ外） |

## 3. 画面構成

1画面構成。左に未配置プール、右に月間カレンダー。

```
┌────────────────────────────────────────────────┐
│  ◀ 2026年7月 ▶   未配置: 8名 / 全体 32名   [👥利用者管理]│
├──────────────┬─────────────────────────────────┤
│ 未配置プール      │  月間カレンダー（日〜土の7列）             │
│ [山田さん ⚠火NG] │ │ 1(水) │ 2(木) │ 3(金) │…            │
│ [佐藤さん]       │ │①田中✓│①      │①山本  │             │
│ [鈴木さん ⚠午前NG]│ │②高橋  │②佐野✓│②      │            │
│  …             │ │③      │③      │③川口  │             │
└──────────────┴─────────────────────────────────┘
```

### 構成要素

- **ヘッダー**：月ナビ（◀ ▶）／「未配置: N名 / 全体 M名」カウンター／「👥利用者管理」ボタン
- **未配置プール（左）**：当月未配置の利用者ピース一覧。ピースには名前＋NG曜日バッジ（⚠火NG）＋自由メモ（あれば）
- **月間カレンダー（右）**：各日に①②③の3枠。枠には配置済みの名前＋時刻＋✓（訪問済み）。空枠は空欄表示＝空き枠がひと目でわかる
- **利用者管理（モーダルまたは別ペイン）**：名前・NG曜日チェック（日〜土）・自由メモの登録／編集／削除

## 4. 操作フロー

### 4.1 配置（D&D）

1. プールのピースを日付枠①②③へドラッグ＆ドロップ
2. ドロップ先がその利用者のNG曜日なら確認ダイアログ「⚠火曜NGの方ですが配置しますか？」
   - OK→配置／キャンセル→プールに戻る
3. 配置時、枠の既定時刻（①13:00 ②14:30 ③16:00）が入る。時刻はクリックで編集可
4. 同じ枠にすでに人がいる場合はドロップ不可（枠は1人まで）

### 4.2 移動・戻し

- 配置済みピースは別の日・別の枠へドラッグで移動（NG曜日警告は移動時も適用）
- プール領域へドラッグで未配置に戻す（時刻・✓はリセット）

### 4.3 訪問済み→来月予約（重要フロー）

1. 配置済みピースの✓をクリック→訪問済み（done: true）
2. 「来月の予約を入れますか？」確認
   - はい→**来月のカレンダー表示に切り替わり**、その利用者のピースが来月のプールに現れた状態になる。ドロップで来月の配置（＝予約）完了。完了後は当月表示に戻れる（月ナビで戻る）
   - いいえ→何もしない（来月の月替わり時にプールから配置）
3. ✓の解除も可能（再クリック）。解除しても入れた来月予約はそのまま残す（削除は来月側で行う）

### 4.4 月替わり

対象月の配置データが存在しない月をはじめて開いたとき、選択ダイアログを表示：

- **前月コピー**：前月と同じ日・同じ枠・同じ時刻で配置を複製
  - 訪問済み✓はコピーしない（全員 done: false に戻す）
  - 来月に存在しない日（例：7/31→8月は存在するが、1/31→2月など）の配置はプール行き
  - すでに当該月に予約済み（4.3で入れた予約）の利用者はコピー対象外（二重配置防止）
- **まっさら**：全員プールから手で配置（既存予約分のみ配置済み表示）

どちらを選んでも、事前に入れた来月予約はその日時に配置済みとして表示される。

## 5. データ構造（localStorage）

ストレージキー：`visit-planner-v1`

```json
{
  "users": [
    { "id": 1, "name": "山田", "ngDays": [2], "memo": "午前は通所" }
  ],
  "placements": {
    "2026-07": [
      { "userId": 1, "date": "2026-07-08", "slot": 1, "time": "13:00", "done": false }
    ]
  },
  "nextId": 2
}
```

- `ngDays`：NG曜日の配列（0=日〜6=土）
- `placements`：`YYYY-MM` キーで月ごとに配置を保持（過去月も振り返り可能）
- `slot`：1〜3（訪問①②③）
- **日付＋時刻を持つ形にして、将来のGoogleカレンダー連携（イベント変換）を容易にする**
- 保存は変更のたびに即時（デバウンス不要の規模）。localStorage は try/catch ラッパー経由

## 6. エッジケース・エラー処理

| ケース | 挙動 |
|--------|------|
| 利用者を削除 | 全月の配置済みピースも削除（確認ダイアログあり） |
| 同じ枠に2人目をドロップ | 受け付けない（視覚的にドロップ不可を示す） |
| localStorage保存失敗（容量超過等） | 画面上部に警告バナー表示 |
| 月替わりダイアログで前月にデータなし | 「前月コピー」を無効化（まっさらのみ） |
| 利用者0名 | プールに「👥利用者管理から登録してください」の案内表示 |
| スマホで開いた場合 | 閲覧のみ（D&D無効）。レイアウトは縦積みで崩れないこと |

## 7. 技術方針

- 単一HTMLファイル・外部依存なし（オフライン動作）
- D&D実装は schedule_v4.html の実績パターンを流用：
  - HTML5 Drag and Drop API
  - `renderAll()` 先頭で D&D 中の再描画ガード
  - drop ハンドラ内で state リセット→再描画の順
  - リスナー多重登録防止（コンテナ再生成 or removeEventListener）
- ロジック（配置・月替わりコピー・NG判定・カウンター計算）は**純関数ブロック**
  （`/* CORE:START */…/* CORE:END */` ＋ `module.exports` ガード）に分離し、
  Node の `node --test` で単体テスト（お客様ノート parseCard 方式）
- 文字コード：UTF-8。Write/Editツールで編集（PowerShell経由で書かない）

## 8. スコープ外（YAGNI）

- Googleカレンダー連携（フェーズ2で別途設計）
- 複数ケアマネ対応・共有機能
- 地区情報・移動時間の最適化
- 印刷対応（要望が出たら追加）
- スマホでの編集操作

## 9. テスト計画

- **純関数の単体テスト（node --test）**：前月コピー（存在しない日・予約済み除外・done リセット）、NG曜日判定、未配置カウンター、枠の空き判定
- **ブラウザ動作確認**：D&D配置／NG警告／移動・プール戻し／✓→来月予約フロー／月替わりダイアログ／利用者管理CRUD／リロード後のデータ保持
- **スマホ表示確認**：閲覧レイアウト・D&D無効
